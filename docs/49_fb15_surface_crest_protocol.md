# FB15 — surface-distance crest count as an independent magnitude cue

Status: **pilot complete; fixed v1 rule and validation population recorded before validation SDT bytes were acquired or scored**. This is a CPU research experiment, not a production classifier, and the local freeze is not externally timestamped. The decision to test this cue follows the [FB14](../reports/2026-09-24_framebridge_fb14.md) finding that high-confidence E1 and strong chord-normal alignment can still undercount by one wrap. We will report both gains and false review burden.

## Physical hypothesis and source

E1 integrates a coarse group-4 gradient-magnitude field; a simple prominence-based peak count in that field could not separate one- and two-wrap development examples. The official Paris 4 `las_008_surf_sdt.ome.zarr.respool_g1` packed field has array shape `[9473,4087,4087]`, exactly `ceil(CT L2 shape / 2)`, compared with group-4 gradient shape `[4737,2044,2044]`. Its metadata claims uint8 surface signed-distance-transform content. We treat the field's oscillating uint8 lobes as a **candidate independent count cue**, not as proven true surface crossings. The developer must not infer physical semantics solely from the filename. The index/table inverse was validated with the repo's `RespoolIndex`; acquired bytes are SHA- and HTTP-range checked. The source index hashes are pinned in `scripts/fetch_fb15_sdt_index.py`.

For each already selected candidate pair in 9.6 µm working xyz, use the same seven E1 chord offsets (−6 to +6 working voxels), but sample the surface field at working xyz reversed to zyx and divided by **2**, every 1 working voxel. Require all seven rays in bounds. On each quantized uint8 profile, smooth with `[0.25,0.5,0.25]`, find positive crests of height ≥130, prominence ≥2, separated by ≥6 samples, then round the median of seven crest counts. This v1 implementation is `src/scroll_lab/sdt_crossings.py` and returns a **nonnegative magnitude cue only**; any signed proposal would retain E1's sign. A missing ray or zero crest count is not silently accepted.

## Method-selection disclosure

The first diagnostic sampled 48 FB08 relative-winding **development** pairs: eight hash-ranked cases in each true-magnitude (1,2,3) × E1-correct/wrong stratum. This is intentionally enriched for E1 errors and therefore **cannot estimate population accuracy**. On these same 48 pairs, frozen E1 was correct on 24; the above crest rule was correct on 40, flagged 20/24 E1 errors as a magnitude disagreement, and flagged 3/24 correct E1 cases. Two stricter crest thresholds were also inspected and performed worse (36/48 and 29/48). Selecting the best of those three on this pilot is explicit method development, not blind validation. The ignored pilot artifacts contain the field profiles; only summaries and hashes belong in Git. The public group-1 surface index required ~32 MiB of metadata and the 48-pair pilot used 6,193,152 bytes of sparse payload.

## Fixed validation population and outcomes

Before evaluating v1 on further SDT bytes, `scripts/build_fb15_validation_candidates.py` hash-ranked FB08 relative **development** pair IDs, excluded **all 41 collections represented in the 48-pair pilot**, and selected the first 300 by `SHA256("FB15-validation-v1:" + ID)`. The selection did not read E1, SDT, normal, or truth outcomes, though the broader FB08 development dataset has already been studied in this project. This yields **300 pairs from 120 distinct non-pilot collections** with true magnitudes 1:168, 2:104, 3:28. The separately inspected FB14 90 absolute-anchor pairs are a stress arm, explicitly **not blind**: their E1/truth outcomes were known before this rule was developed. The validation manifest SHA and rule-source SHA are pinned in `protocols/FB15_sdt_crest_v1_freeze.json` before acquiring validation SDT ranges.

For the 300 collection-disjoint development pairs, report all of the following without changing the v1 rule:

1. Full-population exact absolute magnitude for SDT cue versus E1, and signed exact if E1 sign is retained; by true magnitude and by collection.
2. E1/SDT magnitude agreement coverage, wrong E1 magnitudes flagged, correct E1 magnitudes sent to review, residual wrong E1 magnitudes among agreements, and exact signed precision among agreements. Compare at explicit coverage; withholding is not a claim of zero winding.
3. The same counts inside the unchanged FB08 numeric-eligible gate, separating gate-only from gate-plus-magnitude-agreement. Report how many formerly accepted errors are caught and how many formerly correct relations are reviewed.
4. Ray-count disagreement and zero/invalid crest cases, including failure IDs without republishing CT/field arrays. Since multiple pairs may share points, label pair counts as dependent; use collection-level summaries or bootstrap, not an independent-binomial interval.

Then apply the same rule unchanged to all 90 FB14 pairs as a **retrospective cross-source stress test**, with the four known wrong gate emits called out individually. FB14 success would be promising engineering evidence, not fresh independent validation. Do not tune on either validation arm. If the collection-disjoint evaluation is weak or the cue merely duplicates E1 confidence, keep it as a failed documented experiment. If strong, the next step is a genuinely untouched human-verified positive source and controlled downstream winding/fitter impact, not immediate production export. The `FRAME_REGISTRATION_UNVERIFIED` latch remains closed throughout.
