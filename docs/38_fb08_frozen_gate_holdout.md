# FB08 — frozen normal-applicability gate on reserved Paris 4 annotations

Status: **reproducible CPU holdout experiment; not production constraint export or demonstrated fitter improvement**. The primary threshold, spatial buffer, comparators, and geometry-matched window were recorded in [`protocols/FB08_mixed_constraint_gate_freeze.json`](../protocols/FB08_mixed_constraint_gate_freeze.json) before running holdout E1. That freeze was local, not independently public-timestamped. The development rationale and caveats are in [`37_fb08_mixed_constraint_development_2026-09-23.md`](37_fb08_mixed_constraint_development_2026-09-23.md).

## Result in one paragraph

On 65 held-out relative-winding point collections (1,049 coordinate-selected candidate pairs), the frozen rule emitted **207 conditional nonzero proposals**, of which **190 were exact signed winding differences**: **91.79% precision at 19.73% candidate coverage**. A 2,000-draw bootstrap resampling whole collections gives a 95% percentile interval of **86.49–95.95% precision** and **16.17–24.24% coverage**; these are exploratory uncertainty summaries, not a cure for source bias. On a separate same-winding stress arm, the rule emitted **0/1,742** nonzero proposals after a predeclared 16-working-voxel train/holdout spatial buffer, compared with **1,560/1,742** false nonzero accepts from ungated E1. It also emitted zero on the full unbuffered same arm (2,863 pairs). These are **two separately selected annotation sources**, not a balanced random population of production candidate constraints; do not pool them into one accuracy score.

The result is useful specifically because E1 confidence alone cannot distinguish a plausible crossing chord from an inapplicable along-sheet chord. At confidence ≥0.75, E1 accepts 256 relative holdout proposals with 223 exact (**87.11%**) and also falsely accepts **397/1,742** buffered same-winding candidates. Adding the frozen endpoint-normal alignment raises relative precision to **190/207 = 91.79%** and reduces same-arm false accepts to zero, while giving up 49 relative proposals. The observed difference is an applicability gain, **not** proof that every emitted relation is safe: 17 of 207 are wrong.

## Population, frame, and freeze

The population is the undirected union of each annotated point's three nearest neighbors **within its collection**, using coordinates and collection membership only. Pair orientation is a label-blind SHA-256 bit. Relative truth is the within-collection `wind_a` difference; same-winding truth is zero within its separate source collection. Whole collections, not rows, were assigned to development or holdout. The same arm's random collection split had geographic near-duplicates, so the primary analysis excludes a holdout pair whenever either endpoint is <16 working voxels from any development endpoint in that arm. The coordinate-only plan retains all **1,049** relative pairs and **1,742/2,863** same pairs. The latter span **35** buffered holdout collections; the relative arm spans **65**. Pair-level counts are dependent because pairs reuse points and collections.

The rule requires: E1 answered, predicted `dw ≠ 0`, valid nx/ny-derived normals at both endpoints, minimum absolute dot of the chord with the two endpoint normals ≥**0.75**, and frozen E1 confidence ≥**0.75**. The official Villa `(u8-128)/127` nx/ny normal decoder is matched, with nearest-integer group-4 endpoint sampling explicitly **not** claimed as full dense-fitter parity. `src/scroll_lab/constraint_gate.py` assigns reason codes for withheld and review states. Even numerically eligible rows return `FRAME_REGISTRATION_UNVERIFIED` and remain **review**, because the CT/metadata anchor sanity check does not establish independent exact physical registration. This experiment scores that conditional numeric eligibility; it has not exported production constraints.

The local freeze pins candidate, ray-plan, normal-feature, spatial-buffer, E1-development, comparison and gate-source SHA-256 hashes. The held-out E1 runner verifies freeze kind and candidate/ray-plan hashes; the evaluator verifies the remaining evidence and gate-source hashes. A changed primary threshold or re-filtering after these results would be a **new exploratory experiment**, not this held-out result. The tracked freeze file and its SHA recorded in `artifacts/framebridge/FB08_holdout_e1.json` make the sequence auditable locally, but are not an independently verified preregistration.

## Comparators on the same untouched holdout

The table keeps the two truth arms separate. For the relative arm, `exact / emitted` is signed-winding precision; for the same arm, every emitted nonzero edge is a false accept. Every method here uses the same frozen E1 proposals. The geometry comparator uses umbilicus-centered radial fraction ≥0.75. The two magnitude-only baselines below it use development-fitted cutoffs and are evaluated on **all** relative candidates, not as selective emitters.

| Rule | Relative exact / emitted | Relative coverage | Buffered same false emits / 1,742 |
|---|---:|---:|---:|
| Ungated answered E1 nonzero | 830 / 1,045 = 79.43% | 99.62% | 1,560 |
| E1 confidence ≥0.75 | 223 / 256 = 87.11% | 24.40% | 397 |
| Radial fraction ≥0.75 | 741 / 942 = 78.66% | 89.80% | 1,031 |
| Normal minimum dot ≥0.75 alone | 713 / 876 = 81.39% | 83.51% | 0 |
| **Frozen primary: normal minimum dot ≥0.75 and confidence ≥0.75** | **190 / 207 = 91.79%** | **19.73%** | **0** |
| Development-recorded secondary: normal minimum dot ≥0.50 and confidence ≥0.75 | 223 / 253 = 88.14% | 24.12% | 0 |

As an additional simple control, a radial-sign / two-cutoff magnitude classifier fitted on development collections gets **731/1,049 = 69.69%** exact signed holdout relations. The analogous chord-length magnitude classifier gets **736/1,049 = 70.16%**. E1's 79.12% accuracy over **all answered** relative holdout pairs is higher than both. These baselines are especially important because radial displacement sign alone matches almost every human relative label on development; a tool must add more than this geometric ordering to be interesting.

## Geometry-matched subset

The predeclared common-support window is `|Δz| < 1` and chord length 10–50 working voxels. After spatial buffering it contains **633** relative and **646** same candidates. The primary rule emits **130** relative proposals, **123 exact = 94.62%**, and **0/646** same false proposals. Confidence alone emits **151** relative, **143 exact = 94.70%**, but falsely emits **150/646** same-winding relations. A radial-fraction ≥0.75 rule falsely emits **140/646** same pairs. Thus the key added signal in this matched window is rejecting geometrically inapplicable same-winding pairs; it is not a demonstrated improvement over confidence-only *relative precision* inside that window.

## Accepted-error analysis: the next bottleneck

All **17** wrong primary relative proposals have the **correct sign** and the **wrong magnitude by exactly one wrap**. They are concentrated at larger true offsets: by class, accepted exact/accepted is `-3: 4/7`, `-2: 29/32`, `-1: 63/65`, `+1: 67/67`, `+2: 19/24`, `+3: 8/12`. One accepted E1 output is `+4` and one is `-4`; the rule was intentionally not altered to truncate magnitudes after inspection. Several errors share a collection, e.g. collection 251 contributes four; treating 17 errors as 17 independent cases would overstate certainty. The bounded ID-level failure list is in ignored `artifacts/framebridge/FB08_frozen_gate_holdout.json` without redistributing CT/annotation payloads.

This is the decisive limitation for actual spiral fitting. A geometrically sensible crossing can still have an off-by-one E1 integral. A production gate needs an **additional magnitude-verification or graph-cycle layer**, and the benefit should be measured against a fixed downstream winding-assignment/spiral objective. Developing that layer after seeing these holdout errors is permissible, but it needs a fresh evaluation set or must be labeled exploratory. Do not silently retroactively improve FB08's primary rule.

## Post-hoc fixed-solver graph diagnostic

To test the practical cost of filtering, `scripts/evaluate_fb08_graph_impact.py` feeds three edge sets from the same relative holdout into the repository's **pre-existing deterministic BFS winding solver**. This diagnostic was specified **after** the primary holdout inspection and is not part of the frozen primary protocol. Each collection is its own gauge. The metric enumerates all pairs of annotated nodes that occur in the candidate population; a pair is *comparable* only if the emitted-edge graph connects its nodes. On comparable pairs, the solver's winding difference is compared with human labels. Coverage over *all* possible node pairs is reported alongside conditional accuracy so that disconnecting hard regions cannot masquerade as downstream improvement.

| Emitted edge rule | Edges | Comparable node-pair coverage | Exact among comparable | Exact over all possible node pairs | Solver contradictions |
|---|---:|---:|---:|---:|---:|
| All E1 nonzero | 1,045 | 88.06% | 33.24% | 29.27% | 136 |
| E1 confidence ≥0.75 | 256 | 6.63% | 87.01% | 5.76% | 0 |
| Frozen primary | 207 | **5.02%** | **91.44%** | **4.59%** | 0 |

This is **not** a downstream win for hard-filtering alone. It is evidence that the trust gate yields sparse, higher-precision **seeds**, while other geometric/annotation constraints or soft E1 evidence must preserve connectivity. The BFS solver is not the official spiral fitter, and no GPU or official-fitter output has been compared. A future controlled integration should test accepted edges as hard/high-weight constraints plus explicitly defined soft/review evidence against a common baseline, with both error and coverage on an independent evaluation.

## Official-format integration preview, deliberately not fit

`src/scroll_lab/fb08_pcl_adapter.py` and `scripts/export_fb08_research_pcl.py` transform numerically eligible **development-only** proposals into independent two-point `vc_pointcollections_json` v1 collections with local `wind_a` values `0` and predicted `dw`. The exporter hash-checks the freeze, candidate manifest, development E1 and normal features; requires `--research-only`; writes only under ignored `artifacts/`; and copies **no human `truth_dw`**. It generated **518** paired collections / **1,036** points. The local official Villa `load_point_collection` and `normalise_pcl_winding_annotations` functions read all 518 as annotated relative collections without dropping points. This proves format-level loader compatibility, **not** training semantics or benefit. Every collection carries `registration_verified: false`, and the CLI marks its sidecar `NOT_FOR_PRODUCTION_registration_unverified`. No fitting command was run.

A controlled GPU comparison would need a pinned Villa run configuration using this file as an explicit `relative` PCL input, a common initialization and compute budget, and evaluation on annotations not consumed by the fit. The original human relative/same files must not leak held-out labels into either arm. Using this preview as an extra annotation beside the full original `relative_windings.json` would be invalid evidence of improvement. The official fitter already accepts explicit role-scoped point-collection paths, but exercising that path is a separate experiment. The research preview is a bridge to that test, not permission to enable the production latch.

## Frame and field integrity boundaries

The [official point-collection loader](https://github.com/ScrollPrize/villa/blob/0f7be4a4c9e449caad35537011502cc7ab7bc6fe/spiral-fitting/point_collection.py) reverses `p` for zyx array access. The canonical [2.4 µm Paris 4 CT metadata](https://vesuvius-challenge-open-data.s3.amazonaws.com/PHercParis4/volumes/20260411134726-2.400um-0.2m-78keV-masked.zarr/.zattrs) declares zyx axes, 4× level-2 scale, level-2 shape `[18946,8174,8174]`; the paired group-4 normal field shape `[4737,2044,2044]` is exactly its ceil division by four. A deterministic six-anchor CT spot check across distinct collections and z chunks found nonempty, locally varying CT at those coordinates. This supports the coordinate contract and rules out some gross frame mistakes, not exact registration or parity with the official GPU fitter. The frame latch remains off.

The [Villa grad-magnitude hole report](https://github.com/ScrollPrize/villa/issues/1183) shows why syntactically present bricks and successful byte-range checks cannot establish signal integrity. `scripts/audit_fb08_grad_slices.py` therefore screened every acquired occupied brick in this sparse cache by absolute z: **2,368** z slices had some sampled brick support, **1,664** had at least eight acquired bricks, and **none** of those densely sampled slices was all zero. This rules out the issue's *obvious complete-zero signature in the sampled regions*, not subtler corruption, local signal loss, or holes elsewhere in the full field. Dense/sparse E1 parity is still needed. The normal field is itself a learned prediction, not independent ground truth; it may encode domain-specific priors. The two human annotation sources differ in collection method and geometry, even after the matched-window analysis. The test has not sampled automatic fiber or mesh candidate generation, and there is no demonstrated official spiral-fitter improvement.

## Reproduction and next experiment

The experiment is CPU-only. Raw public annotations, sparse field bytes and derived row-level artifacts are git-ignored in `data/` and `artifacts/`; the challenge data-server license does not authorize redistributing those bytes. Start with the pinned annotation and sparse metadata acquisition described in the development record, then use the provided scripts in this order: candidate manifest, seven-ray grad-magnitude range plan and verified fetch, both normal endpoint plans and verified fetches, normal feature extraction, coordinate-only spatial buffer, development baseline/comparison, tracked freeze, holdout E1, and frozen evaluator. The final two Windows PowerShell commands, assuming those ignored inputs already exist, are:

```powershell
$env:PYTHONPATH='src'
python scripts/run_mixed_candidate_e1.py --candidates artifacts/framebridge/mixed_candidates.json --ray-plan artifacts/framebridge/mixed_all_ray_plan.json --download-manifest data/PHercParis4/lasagna_inputs/mixed_candidate_grad_mag_ranges/download_manifest.json --meta data/PHercParis4/lasagna_inputs/grad_mag_respool_g4_meta.json --coords data/PHercParis4/lasagna_inputs/grad_mag_respool_g4_brick_coords.npy --table data/PHercParis4/lasagna_inputs/grad_mag_respool_g4_table.npy --umbilicus data/PHercParis4/umbilicus.json --partition holdout --protocol-freeze protocols/FB08_mixed_constraint_gate_freeze.json --output artifacts/framebridge/FB08_holdout_e1.json
python scripts/evaluate_fb08_frozen_gate.py --freeze protocols/FB08_mixed_constraint_gate_freeze.json --candidates artifacts/framebridge/mixed_candidates.json --e1 artifacts/framebridge/FB08_holdout_e1.json --normal artifacts/framebridge/FB08_normal_alignment.json --spatial-buffer artifacts/framebridge/FB08_holdout_spatial_buffer.json --umbilicus data/PHercParis4/umbilicus.json --output artifacts/framebridge/FB08_frozen_gate_holdout.json
```

The immediate best-return next experiment is a separate, explicitly exploratory **cycle/magnitude audit** of accepted edges and a fixed downstream graph-assignment comparison. GPU Colab is **not** needed for the completed FB08 result. It becomes relevant only if we construct a reproducible official-fitter input adapter, define the same downstream objective and budget for baseline/gated fits, and obtain an evaluation that cannot be won by filtering away hard constraints. The strongest defensible public story at present is a compact, reason-coded trust gate that sharply reduces false nonzero use of an estimator on same-winding candidate geometry while exposing its remaining one-wrap magnitude errors.
